# npm: how each phase is done

Coverage: **complete**, from two finished runs (get-title-at-url 2.0.0 to 3.0.0, 2026-09-24 and 25, a library with a CLI; seeded-random-utilities 1.1.4 to 2.0.0, 2026-09-25, a deterministic library). Every version number below was verified on 2026-09-24 or 25; re-verify any that is older than three months when you use it (RESEARCH.md carries the dates). The phase list and the shared rules are in [../SKILL.md](../SKILL.md); this file is the npm column.

## Phase 0: survey and baseline

- `scripts/survey-npm.sh PACKAGE [OWNER/REPO]` prints the registry facts (versions, dist-tags, attestations, downloads, dependents, tarball file list, each runtime dependency's distance from current) and the GitHub facts (settings, security features, issues, pull requests, alerts, webhooks, secrets, environments, workflows, forks, dead-service files and badges). Save the output under `ai-docs/notes/` and cite it from the plan.
- In the clone: read every source and test file, `package.json`, the build config, the README, every dotfile, and the published tarball (`npm pack PACKAGE@OLD`; it can hold files the repository does not, such as an unregistered `cli.js`, `.travis.yml` or `.vscode/`). Diff the tarball against the repository with `diff --strip-trailing-cr` file by file: the repository's master can be ahead of the published version (is-an-image-url: a bot pull request moved `meow` from ^5 to ^6.1.0 after 1.0.4, never published), and a tarball published from Windows has CRLF files (count byte 13 with `scripts/check-line-endings.mjs`) (2026-09-25).
- A package with a `bin`: install the published version in a scratch project and run the bin with `--help` and one ordinary input before planning. The CLI can be broken while the library works: is-an-image-url 1.0.4's CLI has failed on every call since 2019 because meow 5 stopped accepting `help` as an array, and no issue was ever filed. Run the previous version too when the current one fails, to learn the contract the README describes (2026-09-25).
- Leaked credentials: `.travis.yml`, `.npmrc`, `.env`, workflow files, `package.json` scripts (`snyk auth <uuid>`, `--token`), and history (`git log -p --all | grep -iE 'auth [0-9a-f]{8}-|_authToken|token'`) and old published versions (`npm view PACKAGE@V scripts`; npm masks a token as `***`, which still shows one was there). A token in history is burned even after the file goes; the maintainer revokes it at the provider. stack-exchange-markdown-retriever had a Snyk token in 1.1.4 and 1.1.5 that the kickoff expected not to exist (2026-09-26).
- Dead services and where each one leaves traces: Travis CI (travis-ci.org and .com badge, `.travis.yml`, webhook), David (david-dm.org badge; the service is gone), Gitter (badge), SonarCloud (`.sonarcloud.properties`, badge, OAuth app), codecov and Coveralls (`codecov.yml`, `.coveralls.yml`, token in `.travis.yml`, badge, webhook, OAuth app), Snyk (`.snyk`, badge, two webhooks, OAuth app, `snyk-fix-*` branches and pull requests under the maintainer's name). List badge, config file, webhook and app for each.
- README images and badges: `node scripts/check-readme-images.mjs README.md` on the clone and on `package/README.md` from the published tarball (they can differ). It flags dead-service badges, including shields.io badges that answer 200 but say "not found", HTTP errors, and relative paths, which break on npmjs.com because the page renders the README from the tarball. Save the output with the survey; the plan's badges-and-images table decides each one (verified 2026-09-25 on replace-string-at-position 1.0.4: 7 of 8 images to fix).
- Baseline: run the old install, build and tests as they are and record the result. Windows trap: 2016 to 2019 scripts that call `./node_modules/.bin/...` fail under cmd.exe, npm's script shell; run `npm --script-shell "C:/Program Files/Git/bin/bash.exe" test`. An old `xo` or `ava` may not install on Node 24 at all; record that too, it is a fact about the package. Do it in a scratch clone (`git clone -q <repo> <scratchpad>/baseline`) so the old install leaves no lockfile in the repository. A test script that starts with `snyk test` stops at a 401 without a Snyk login, so also run each tool alone from inside the scratch clone and record each result (2026-09-25: xo 0.15 crashes on Node 24 with `util.isDate is not a function`; `ava: "*"` resolves to ava 8, which refuses `import x from './'`). When the old suite cannot run at all, say so in the plan: the golden capture is then the only baseline.
- Dependents: the registry gives only a count. `survey-npm.sh` lists the public repositories whose `package.json` names the package (`gh search code`); read each call site, because what the dependents pass decides what the new major may refuse (2026-09-25: the inventory knew one dependent of replace-string-at-position, the search found two).
- Runtime dependencies: `npm view DEP versions time deprecated`. For each major behind: what changed, and whether the package's observable behaviour depends on the dependency's internals (seeded sequences, hashing, sort order, parsing quirks). Test it empirically in two scratch projects before deciding.
- Caret ranges: a fresh `npm install PACKAGE@OLD` can resolve a newer dependency than the old lockfile pinned (`^0.1.2` installed 0.1.5). Record the versions the capture ran against; test every version the range covers if a dependency shapes the output.
- Golden capture: copy `scripts/golden-capture-npm.template.cjs` and `templates/npm/test/golden/codec.cjs` into a scratch project that installed the published old version, fill in every public method with normal, edge and odd inputs (empty strings, numbers where strings go, null and undefined, NaN, negative and out-of-range numbers, huge values, array-likes and Sets, wrapper objects, emoji), run it, commit the JSON and the script under `test/golden/`. Check every claim the kickoff or the survey made against the capture's quirks section.
- Asynchronous or network packages (a callback, a Promise, HTTP requests): the template is synchronous, so write the capture around it (worked example: is-an-image-url `test/golden/`, 2026-09-25). Start a local fixture server in the capture script (one route per behaviour: each content type, statuses, redirects and a loop, a missing header, a slow and a stalled response, a large body, a second host name, a closed port) and never let a recorded case touch the internet. Record per case: what the call returned or threw, every callback invocation with its arguments and whether it ran before the call returned (synchronous callbacks are a quirk the rewrite usually changes), uncaught exceptions (a `process.on('uncaughtException')` handler scoped to the case), and every request the server saw (method, path, raw headers in order, the port replaced by a placeholder). Put `{{base}}`-style placeholders in the arguments so the golden test can start the same server on another port. Record the bin's stdout, exit status and first error line for each CLI case. Round timings, keep them in the quirks, run the capture twice and diff: the file must be identical. Then probe the replacement transport (Node's `fetch`) on the same routes, so the plan knows which answers and request lists will differ.
- A package that always calls one fixed HTTPS host (an API client: stack-exchange-markdown-retriever, 2026-09-26): the URL cannot take a `{{base}}`. request 2.88 honours `HTTPS_PROXY`, so the capture sets it to the fixture server, which handles `connect` itself: it records the CONNECT, answers `200 Connection Established` and hands the socket to an in-process `https.createServer` with a throwaway certificate the capture makes with `openssl req -x509 ... -subj /CN=<host> -addext subjectAltName=DNS:<host>` (`NODE_TLS_REJECT_UNAUTHORIZED=0` in the capture process only). The proxy never forwards, refuses any other host, and the capture stops when a case that should request reached no proxy. Route behaviour by the id in the path, so the new code reaches the same routes. The new code's suites replace `globalThis.fetch` with a wrapper that checks the origin, records the URL and fetches the same path from the fixture server over HTTP; child processes (the bin, a case whose callback throws) load the wrapper with `node --import <file URL>`. Worked example: stack-exchange-markdown-retriever `test/golden/` and `test/helpers/api.js`.
- A package that looks up links found in its input (many hosts; markdown-plain-link-replacer, 2026-09-27; L-045): request 2.88 honours HTTP_PROXY for http links (it sends the absolute URL to the proxy) as well as HTTPS_PROXY (CONNECT), so one fixture proxy serves every host, routed by path, with no DNS changes; the server also reads an `x-fixture-url` header so the new code's fetch wrapper reaches the same routes directly. Guard the capture at the socket rather than per case: wrap `net.Socket.prototype.connect` so any host but 127.0.0.1 or localhost throws, reading the options from `Array.isArray(args[0]) ? args[0][0] : args[0]`. `net.connect()` and `net.createConnection()` (plain http, from `http.request` and from `fetch`) hand the method their arguments already normalised into one array, so a wrapper that reads `args[0].host` stops only `tls.connect()` and lets plain http through (Node 20.20.2 and 24.18.0, 2026-09-29; L-124). Test the guard once before trusting it, with a host that cannot resolve: `fetch('http://guard-test.invalid/')` must fail with the guard's message, not `ENOTFOUND`. Print the cases that made no request for review, and grep the golden file for the guard's message (0 expected). A per-case "must request" check aborts on cases that legitimately send nothing (a throw before the request, a URL request refuses).
- Replaying a capture against the next major (the wiki's Versions and upgrading page replays it against the old version installed today and against the new one; wikiwright L-113, L-123 here). The capture loads the package by name, so copy it and its helpers into a scratch project with the new version installed and run it there unchanged. The template's `binPath()` and `dependency()` keep two things from breaking: a bin that moved (`cli.js` to `dist/cli.mjs`) and a dependency the new major dropped. A network capture routed through a proxy has two more, measured on markdown-plain-link-replacer 1.1.16 against 2.0.0 on 2026-09-29 (Node 24.18.0 and 20.20.2). First, the new code's `fetch` ignores `HTTP_PROXY` unless the process started with `NODE_USE_ENV_PROXY=1` and the variables already set (Node reads both at startup; Node 20 has no such variable), and a capture sets them only once its server listens. Second, Node's proxy support and undici tunnel `http:` links with `CONNECT host:80`, so a fixture that hands every CONNECT to its TLS server fails every http link. The replay therefore patched two copies, never the committed files: after the variables are set, `require('undici').setGlobalDispatcher(new EnvHttpProxyAgent())` in the capture and `NODE_OPTIONS=--require <that file>` for its CLI children (forward slashes: NODE_OPTIONS reads a backslash as an escape), and a fixture `connect` handler that sends port 80 to the plain server. `NODE_TLS_REJECT_UNAUTHORIZED=0`, which the capture sets at run time, is read per connection and covered the certificate. For a new capture, route CONNECT by port from the start, and keep the proxy setup in one function the replay can extend. Compare the answer, the timing and the request lists apart, the request lists without the CONNECT lines and without how each request arrived; 1.1.16 today gave 154 of 154 calls and 18 of 18 command line runs, identical.
- A package that reads and writes files (format-json-files, 2026-09-26; L-043): the trees are data in a committed `capture-fixtures.cjs`, and each case builds a fresh temporary tree; stamp every file with a fixed mtime so `written` is recorded without comparing bytes; put `{{root}}` for the tree's path in arguments and outputs; record the CLI's stderr as its error lines only (stack traces carry the Node version and paths); keep deep-nesting fixtures near 40 levels (2000 levels formatted to 16 MB of golden JSON). Windows cannot make file symbolic links without developer mode, while every CI runner (windows-latest too) can: record which links the capture could not make, and name the link behaviour as an exception in the golden test by reason, or capture on Linux when links matter (L-041).
- Read claims about error paths against the capture, not the code: "the throw inside the callback crashes the caller" was wrong for stack-exchange-markdown-retriever because the throw sat inside the `try` that fed the callback, and the same `try` called a throwing user callback a second time (2026-09-26).
- Ported arithmetic: golden fixtures only cover the draws they record. Read every ported expression for unwrapped sums, float multiplies and signed-versus-unsigned words; write oracles from the authors' reference code (BigInt versions of the C) for any algorithmic package.
- Docs setup happens here too: `everlast-setup` (mode repo, sync push; when the run was told not to push, register with `--sync off`, because the SessionEnd hook of sync push commits and pushes `ai-docs/` by itself, and switch to push at the plan review), AGENTS.md, CLAUDE.md with the `@AGENTS.md` import, the Copilot pointer, the plan from [plan-skeleton.md](plan-skeleton.md).

Rolldown's `outputOptions.exports: 'default'` fails the declaration build; two configs cannot share `exports: true`, so the entry points are written by hand and pinned by the shape test. Add `banner: {js: "'use strict';"}` to the CommonJS config (the Phase 3 review found the function sloppy-mode without it) and a TypeScript 5.9 consumer fixture with esModuleInterop off (TypeScript 6 cannot turn it off) that compiles and runs `import = require()`, `import * as` and the default import. Package-specific decisions that recur: every published name keeps working (a misspelled or oddly ordered method gets a new name and stays as a deprecated alias with a JSDoc `@deprecated` tag for one major); fixes to behaviour users may rely on go behind new names; unbounded allocations driven by a caller's number are replaced by algorithms bounded by the output size; never-throw versus typed errors is chosen per package and written in the plan's API section; kickoff wishes can conflict (bounded by the amount versus bit for bit), so the plan tests each requested fix against the promise and says when they clash; the new major's own additions get a second golden file (`2.0.0.json`) captured from the release build so later minors keep them; cheap compatibility shims are worth it (a deprecated static `default` for `new X.default(seed)`, an `interface` rather than a type alias so augmentation compiles).

## Phase 2: rewrite

- Branch `v<major>` from `master`. Remove the dead files (`.travis.yml`, `.snyk`, `.sonarcloud.properties`, `.npmignore`, old lint, build and test configs, `sample/`, the old lockfile) and add the templates from `templates/npm/` (README there says which is which), replacing every `{{...}}` and `TEMPLATE:` block.
- Write the golden test first; the first build must pass every captured case before any new method is written. For a callback or network package, build each case's expectation as the recording with the exception's changes applied (answer, request list, throws, Promise), assert the request sequence as method and path, and replay every callback case through the Promise form too (is-an-image-url's test/golden/golden.test.js). A fixture server that destroys its sockets between cases must wait about 30 ms before the next request, or fetch reuses a dead pooled socket on Node 20, 22 and 26 (L-023). Canary (2026-09-26): once the golden test is green, change one line in `src/` that a captured case reaches, run `npm run build && npm run test:golden` (or the script that runs it) and log the failing count, then `git checkout -- src/`, rebuild, rerun and log green; a canary that stays green means the test imports the wrong build or the case list is empty. Untouched: `git diff --exit-code <phase-0 sha> -- test/golden/*.json test/golden/capture*.cjs test/golden/codec.cjs` prints nothing; `scripts/preflight-tag-npm.sh` runs the same check against the commit that first added the golden JSON.
- Commit `src/` before the first canary: while it is untracked, `git checkout -- src/` reverts nothing and the "reverted" run stays red (L-047, 2026-09-27).
- Before writing the golden test's exceptions, run every recorded case through the first build in a scratch script and list each difference: every one maps to a plan item or is a bug in `src/`, and new items go to the plan and the pull request's "For review" list (three did in markdown-plain-link-replacer). When the output passes through a dependency's new major (a title, a formatted value), apply that change mechanically in the golden test: swap the recorded old answer for the new dependency's answer, which the test asks the dependency for itself, and make the cases whose reading changed in other ways named exceptions with explicit outputs (L-046).
- A package that keeps runtime dependencies which fetch: route every fetch in the tests through a `globalThis.fetch` wrapper that sends the URL to the fixture server with the meant URL in a header and follows redirects itself (markdown-plain-link-replacer `test/helpers/web.js`), and stub fetch in-process for unit suites. An inlined old dependency gets an oracle recorded in a scratch project (a JSON file with its capture script) or its own expression written into the test, not a dev dependency with an old tree. The shape test lists the CommonJS build's allowed `require()` names and runs it in a bare vm context whose `require` serves only those (L-051, 2026-09-27).
- Inlined dependencies: code and licence copied from the exact version's tarball, regex flags kept, platform-dependent calls (`path`, `os`) named in the plan with test cases for the platform the new code follows (L-024).
- Network packages: clamp a user timeout to 2147483647 ms; functional tests for a redirect to another host and to a credentialed URL, listener cleanup on a shared signal, and a one-call process exiting well before the default timeout; the docs never present an input allow-list as SSRF protection, since redirects bypass it (L-026).
- Then `src/`, the rest of `test/`, README (three live badges: npm version, CI, downloads, and every other image as the plan's table decided, with absolute raw.githubusercontent.com URLs pinned to a tag for kept screenshots; install, usage for ESM, CommonJS, TypeScript, Deno, Bun and browsers; API; behaviour at the edges; migration; limits and what the package is not), CHANGELOG (Keep a Changelog; the first paragraph of the new major states the compatibility promise and lists every exception, rare call patterns included), SECURITY.md, AGENTS.md.
- Verify on Node 24 (lint, typecheck, build, test, check, coverage, consumers), then the suites on Node 20, 22 and 26 (portable Node builds in the scratchpad), then from a fresh clone. Record each in the log.
- Push the branch and open the pull request with a "For review" list: departures from the plan and anything the maintainer has not ruled on.

## Phase 3: review

`prompts/review-subagent.md`, filled in, run read-only in a fresh context (background) while the pull request description is written. Fix or answer every finding, commit, note the review's summary on the pull request. Then fuzz the published old version against the new build (L-052): install it in a scratch folder, replace its network modules through `Module._load`, force `setTimeout` to 0, and render a marker template. Seed the generator with whole inputs, group the differences by cause, drop the numbered exceptions and read every remaining group. It found two bugs the review missed. In timing tests, measure staggered events from the first one, not the previous one (L-053).

## Phase 4: CI, settings, merge, cleanup

- `ci.yml`, `release.yml`, `verify-published.yml`, `dependabot.yml` from the templates; actions pinned to commit SHAs (checkout v7.0.1 `3d3c42e5aac5ba805825da76410c181273ba90b1`, setup-node v7.0.0 `820762786026740c76f36085b0efc47a31fe5020`, upload-artifact v7.0.1 `043fb46d1a93c77aae656e7c1c64a875d1fc6a0a`, download-artifact v8.0.1 `3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c`, setup-bun v2.2.0 `0c5077e51419868618aeaa5fe8019c62421857d6`, setup-deno v2.0.5 `22d081ff2d3a40755e97629de92e3bcbfa7cf2ed`, as of 2026-09-25; re-check with `gh api repos/OWNER/REPO/git/ref/tags/vX`); `actionlint` clean. `permissions: contents: read` at the top, `id-token: write` and `contents: write` only in the publish job, `persist-credentials: false` on every checkout.
- CI green on the pull request; record the run id. Ruleset on `master` before the merge, with the other settings (copy get-title-at-url's 24003504: `gh api repos/m4bwav/get-title-at-url/rulesets/24003504 --jq '{name,target,enforcement,conditions,bypass_actors,rules}' | gh api -X POST repos/OWNER/REPO/rulesets --input -`; deletion and non-fast-forward blocked, required check `ci`, admin bypass). Squash-merge with `gh pr merge --squash --match-head-commit <full SHA>` after the maintainer's review; when the maintainer merges it themselves, read the method and SHA with `gh pr view N --json mergeCommit,mergedAt` and cite that SHA (L-027).
- Under an automatic permission mode, take the go for the whole cleanup list in the session before the first write, and put the commands in the HANDOFF for anything refused (L-028). Claude Code's auto mode blocks the cleanup script, even its dry run, until the maintainer adds a Bash allow rule. It blocks the security settings (secret scanning, vulnerability reporting, workflow permissions, rulesets on the branch) as a permission grant even then, so hand those commands over. A maintainer running the scripts from PowerShell gets `gh: command not found`; they need Git Bash, run from the repository directory (L-054).
- Cleanup, each with the maintainer's prior OK for deletions. Shortcut: write the plan's disposition table as a tab-separated file (`pr`, `branch`, `hook` lines, `{SHA}` for the merge commit) and run `scripts/post-merge-cleanup.sh OWNER/REPO PR FILE --ruleset-from m4bwav/get-title-at-url/24003504 --tag-ruleset`; its dry run is the list the maintainer says go to, then `--apply` (it reads the merge SHA and method, refuses while alerts are open, copies the ruleset if none). ## Phase 5 and 6: release rehearsal, release, verification

- Trusted publisher, once, by the maintainer in a browser: the package's Settings on npmjs.com, Trusted Publisher, GitHub Actions; organization or user OWNER, repository REPO, workflow filename `release.yml` (filename only; it must exist in `.github/workflows/`), environment blank; "Allow npm publish" unticked so the workflow can only stage; publishing access "Require two-factor authentication and disallow bypass 2fa tokens". The provider and required fields cannot be changed later; renaming the workflow file breaks publishing. `package.json` `repository.url` must be `git+https://github.com/OWNER/REPO.git` exactly.
- Requirements in the workflow: Node 24 in the publish job (Node 22 ships npm 10.9, which can neither exchange an OIDC token, npm 11.5.1, nor stage, npm 11.15), `registry-url: https://registry.npmjs.org`, no `NODE_AUTH_TOKEN`, no `--provenance` (npm adds provenance itself for a public repository and package), always `--tag next` or `--tag latest` (npm 11.19 refuses a prerelease staged without a tag).
- Before the first tag: the CHANGELOG heading must read `## [X.0.0]` (with ` - Unreleased` or a date), never Keep a Changelog's bare `## [Unreleased]`, which `release.yml` cannot find; its link definition must be renamed to `[X.0.0]:` too, or xo fails on the unused definition. Run `npm run lint`, `npm run typecheck` and `npm test` after any edit, even a one-line changelog fix, before `npm version` (L-029).
- Rehearsal: `npm version X.0.0-beta.1`, `git push --follow-tags` (under an automatic permission mode, say plainly that the maintainer has asked for it; the tag starts the publish, L-028); the run logs "Staging to https://registry.npmjs.org/ with tag next" and a stage id. Stop while the maintainer approves in the Staged Packages tab (2FA). Then `npm view PACKAGE dist-tags` (`latest` unchanged, `next` the beta), `gh workflow run verify-published.yml -f version=X.0.0-beta.1`, and `npm audit signatures` in a scratch project that installed it (one verified signature and one verified attestation).
- Release: date the changelog heading, `npm version X.0.0`, push, stop for the approval, then the same three checks plus `gh release view vX.0.0` and `npm view PACKAGE dist.attestations`.
- Shortcuts (each replaces a chain that cost several calls and two burned prerelease numbers in is-an-image-url): `scripts/preflight-tag-npm.sh VERSION REPO_DIR` before every `npm version` (tree, branch, tag free, changelog heading and date, lint, typecheck, check, test, workflow shell; prints READY with the two commands); `scripts/watch-run.sh OWNER/REPO release.yml` after the push (verdict per job, the stage id and provenance lines, or the failing step's last 40 lines); after the approval `scripts/verify-registry-npm.sh PACKAGE VERSION OWNER/REPO` (dist-tags, provenance, not deprecated, scratch install with `npm audit signatures`, require/import/bin smoke, GitHub Release, verify-published run).
- The `next` rule: `next` may point at `latest` or a newer prerelease, never at a version below `latest`, and it may be absent. After X.0.0 is live it still points to the last beta, so fix it in the maintainer's terminal (2FA): `npm dist-tag add PACKAGE@X.0.0 next` (default; keeps `npm i PACKAGE@next` working, semantic-release's channel model) or `npm dist-tag rm PACKAGE next`. Detect without a login: `scripts/check-next-tag-npm.sh PACKAGE [PACKAGE...]` prints STALE and both fix commands when `next` is below `latest` in semver order (X.0.0-beta.1 < X.0.0); run it after every release and over the whole inventory in an audit (npm search by maintainer misses packages). The npmjs.com page lags the registry, so trust the CLI read-back. Automation is not possible yet: trusted publishing (OIDC) covers publish only, and `npm dist-tag` needs interactive 2FA (npm/cli#8547 open; npm/api-documentation PR #79 draft, 2026-09-18). Maintainer's rule, 2026-09-27.
- `npm deprecate` and `npm dist-tag` fail with EOTP from an agent's shell: without a TTY, `--auth-type=web` does not wait and the auth URL is masked. The maintainer runs them in his own terminal; the agent gives the full command and afterwards reads the result back (L-037, 2026-09-26).
- Tag pushes (`npm version` plus `git push --follow-tags`) run in the main session. A subagent that the permission classifier refuses reports back and stops; it does not ask the maintainer for "run it" (L-038, 2026-09-26).
- Deprecating the old major (D4-style) is CLI only: npmjs.com's Deprecate button deprecates every version, the new major included. Give the maintainer the exact command with the full message, never a placeholder (a `"..."` shorthand in a chat reply was copied verbatim and became the live message, L-031): `npm deprecate PACKAGE@"<X" "<message>"`; the maintainer's npm login on the machine answers the 2FA with a browser link. Check it with `npm view PACKAGE@OLD deprecated`.
- npmjs.com's package page is cached apart from the registry: minutes after an approval it can still show the old version's README and badges while `curl -s https://registry.npmjs.org/PACKAGE` already serves the new `readme`. Verify the README from the packument and from `https://www.npmjs.com/package/PACKAGE/v/VERSION`, and tell the maintainer the main page catches up later (replace-string-at-position 2.0.0, 2026-09-25).
- Deno within 24 hours of a publish needs `--minimum-dependency-age=0` (Deno 2.9); the template passes it.
- Deprecating an old major or a bad version is `npm deprecate PACKAGE@RANGE "message"` from a logged-in CLI with 2FA: the maintainer's task, not the workflow's. Unpublishing is limited to 72 hours and versions with no dependents; do not plan on it.

## Retrofit

The npm side of [retrofit.md](retrofit.md), from seeded-random-utilities 2.0.0 to 2.0.1 (2026-09-29; m4bwav/seeded-random-utilities pull request #18, its plan, gap audit and log under `ai-docs/`).

- Every version: `npm pack PACKAGE@V` for each version lists its files; install each in its own scratch project and run the contract's capture there (seconds each). Diff the built JavaScript of versions that answer differently: seeded-random-utilities 1.0.0 to 1.1.3 have identical `dist/` and differ from 1.1.4 in one expression, `Math.random()` for `this.random()` in `shuffle`, plus an interface rename in the declarations; the CHANGELOG called 1.1.4 a re-publish and put the rename in 1.1.0 (L-126).
- Per-version downloads: `curl -s https://api.npmjs.org/versions/PACKAGE/last-week` (the survey's monthly figure has no split). A prerelease can show real numbers (2.0.0-beta.1: 134 in a week), so compare its tarball with the release's before deciding it needs its own recording (identical `dist/` there).
- Reproducible build: build the tag's source and compare `dist/` with the published tarball's, file by file after `tar -xzf` (tsdown 0.23.0 was byte-identical on Windows and Linux).
- Existing recordings made before the codec: replay with the capture as committed; add a new capture of the latest version from npm through `codec.cjs`, with error classes, odd inputs, draw counts where the package is stateful (one more call recorded after each case), the export shape, and an ASCII writer (the template has it). Run it on Node 20, 22, 24 and 26 and under Bun and Deno (`npm install deno bun` in a scratch folder): one recording serves every runtime when only engine-worded messages differ, which the header lists.
- The replay of scenario cases (stateful code the capture ran by name) is written again in the test under the same names, with a test that fails when a recorded name has no replay.
- Helper scripts go in `scripts/`, not `test/`: xo's node-test rules read anything under `test/` as a test file and refuse importing it from a script.
- The release gate (templates/npm release.yml): `npm version` pushes the commit and the tag at once, so release.yml waits for ci.yml's push run on master for that commit (the actions runs API with `event=push&branch=master`, actions read), not any check run: a pull request run on the same SHA tested a merge ref (L-127). ci.yml gives every run that is not a pull request a concurrency group of its own commit, because `cancel-in-progress: false` still lets a newer run replace a pending one. `npm run check` runs before `npm test` in release.yml, because attw packs with lifecycle scripts and `prepack` rebuilds `dist/`. The tarball is packed once with `--ignore-scripts`, checked by `scripts/check-tarball.mjs`, its SHA-512 passed as a job output and checked with `sha512sum -c` before the consumers and before staging. Test the gate's verdict against real commits: one with a green push run, one with only a pull request run, one with a failed push run (another repository's is fine), and a bad repository name (L-128).

## Traps (Windows PC, verified 2026-09-25)

- publint packs without lifecycle scripts, so `npm run check` needs a build first.
- `gh pr merge --match-head-commit` wants the full SHA.
- c8 needs `--exclude-after-remap` to report `src/`; CLI coverage needs `dist/cli.mjs.map` built (kept out of the tarball by `files`).
- With `sourcemap: true`, tsdown 0.23.0 leaves a `sourceMappingURL` comment in the declaration files though no declaration map is written; the template's `build:done` hook strips it.
- The `v` regex flag is a syntax error in Safari 16 and Chrome before 112; the xo config requires `u`.
- rand-seed 3's `exports` map hides its `package.json` from `require()`; a capture script reads it from disk.
- Node's `TextDecoder` decodes windows-1252 bytes 0x80 to 0x9F as C1 controls on Node 20 (from 20.18.3), 22.13.0 to 22.22.0 and 24.0.0 to 24.13.0; decode that family yourself.
- Everlast doc lint: it reads any at-sign word as a social handle (JSDoc tags, the CLAUDE.md import line, npm scopes) and `id-token: write` as a credential, flags email addresses (the survey masks the maintainers' now), wants a `## Reasons` heading in decisions, `## Next single action` in the handoff, `## Status` in a plan and `## Summary` in a note, and wants paths of files that do not exist yet written without backticks (verified 2026-09-25).
- Git Bash's GNU tar reads `C:/...` as a remote host ("Cannot connect to C: resolve failed"); extract with a relative path or `--force-local`.
- Node 20 and 22 print TAP when stdout is not a terminal (`# pass 172`), Node 24 and later the spec reporter (`ℹ pass 172`); grep for both when checking portable Node builds, or an empty grep looks like a pass (2026-09-25).
- zizmor: an inline `# zizmor: ignore[...]` inside a `run: |` block is shell text, not a YAML comment, and is ignored; the template's `.github/zizmor.yml` suppresses `adhoc-packages` for verify-published.yml, whose job is installing the version just published. Run `uvx zizmor --offline .` from the repository root so `dependabot.yml` is audited too (it wants a `cooldown`, now in the template) (2026-09-25).
- `npm exec` and `npx` run in the session's working directory, not the `--prefix` folder; run old tools from a subshell inside the scratch clone.
- `npm --prefix DIR init -y` also writes to the working directory: after a stray `cd` into the repository it normalised the repository's package.json, which went into the Phase 0 commit. Make scratch projects with `(mkdir DIR && cd DIR && npm init -y)` and check `git status --short` before each Phase 0 commit (L-044, 2026-09-27).
- `xo --fix` removes `| null` from public types, rewrites `http://` to `https://` inside comments, capitalises package names that start a comment, and rewrites strings as `String.raw` (which cannot end in a backslash); stage first and read `git diff src/` (L-025, 2026-09-26).
- `import-x/order` reads a local `const require = createRequire(...)` followed by `require(...)` calls after a blank line as a second import group; name the variable `load` (2026-09-26).
- Portable Node lines without nvm: `npx -y -p node@20 node --test <files>` runs the built suites on Node 20 (and 22, 26); pass `--test-reporter=spec` so every line prints the `ℹ pass` summary (2026-09-26).
- actionlint is not on npm: `gh release download -R rhysd/actionlint -p '*windows_amd64.zip'` into the scratchpad, unzip, and run it from the repository root (1.7.12, 2026-09-26). Without shellcheck on PATH it checks no shell at all: run `python scripts/check-workflow-shell.py REPO` too (L-030; a truncated `[ "$answer" = "true"` in verify-published.yml passed actionlint and failed the Bun job after the beta was live).
- `npx --no <bin> -a 1010` gives the bin's short flags to npm exec (`-a` vanished and the bin fetched a question); put `--` before the bin: `npx --no -- <bin> -a 1010`, also for `--version` (2026-09-26).
- `node --import D:\path\preload.mjs` fails with ERR_UNSUPPORTED_ESM_URL_SCHEME (the drive letter reads as a scheme); pass `pathToFileURL(path).href` or `new URL(..., import.meta.url).href` (2026-09-26).
- `DecompressionStream` answers edge cases differently per Node line: gzip followed by junk fails on 24.18 and is ignored on 26; two gzip members are both read on 24.18 and only the first on 24.21 and 26. zlib.unzip differs from both. Pin only cases every line agrees on (2026-09-26).
- A golden case that waits on a server that never answers can fail in a full run with `UND_ERR_SOCKET other side closed` a second after the request (a pooled connection the shared fixture server closed); give that case a fixture server of its own on a new port (2026-09-26).

- xo caches per file in `node_modules/.cache/xo-linter`, and a cache older than an edit hides that file's errors; CI then fails what passed locally. Clear it before the last local lint before a push; `preflight-tag-npm.sh` does (L-040, 2026-09-27).
- `release.yml` writes `release-notes.md` into the checkout before it lints, and xo lints Markdown: an unused link definition there fails the build and burns the tag. The template's xo config and `.gitignore` ignore the file; check a package's own config keeps that ignore (L-039, 2026-09-27).
- `xo --fix` can bring in APIs newer than the Node floor: it rewrote `new Promise(resolve => ...)` into `Promise.withResolvers()` (Node 22+) and every golden case failed on Node 20. Run the suites on the floor line after any `--fix`; the template turns unicorn/prefer-promise-with-resolvers off while the floor is 20 (L-049, 2026-09-27).
- The editor tools decode `\u` escapes in the content they write (a comment `[a-z\u00a1-\uffff]` landed as the characters): write them doubled and grep new files for non-ASCII. A chain `npm test | grep ... && git commit` commits after failures, because grep's status passes; check the summary, then commit in a separate call (L-050, 2026-09-27).
- A release gate written as `[ "$(tool ...)" != 0 ]` passes when the tool is missing (Git Bash has no jq): compute one verdict word with gh's own `--jq` and switch on exact words with a stopping default (L-128, 2026-09-29).
- `node --test` summaries start with a three-byte `ℹ`; a grep for `^. (pass|fail)` matches nothing in a C locale and an empty grep reads as a pass. Grep for ` (tests|pass|fail) [0-9]+$` (2026-09-29).
- Review findings for packages that scan text: a regex over a whole file overflows V8's backtrack stack near 10 million characters (use `indexOf` loops, test sizes in the millions); `JSON.stringify` writes exact doubles above 2^53 with other digits than the source had (L-043, 2026-09-26).
