# Survey and golden capture (Phase 0)

## Survey (Phase 0)

Run `scripts/survey-<system>.sh`; it prints each command above its output, so the file is its own evidence. Then read the clone and the published artifact (it can hold files the repository does not). Record: versions and dates, downloads, dependents by name and how each calls the package, the export shape and how the old README says to call it, runtime dependencies and their distance from current (and whether the package's observable behaviour depends on a dependency's internals), every public method without a direct test, bugs and API oddities (misspellings, odd argument orders, wrong README claims, unbounded loops or allocations on caller input, dead branches, tests asserting the wrong bound), issues and pull requests by author and kind, forks, alerts, every workflow's action pins and their runtimes (a `node20` action stopped running on 2026-09-23, so an old pin fails on day one), webhooks, secrets, security features, dead services (badge, config file, webhook, OAuth app for each), leaked credentials in files and in history. Survey claims can be wrong: check every one against the golden capture, and write the corrections into the kickoff prompt's last section.

## Golden capture (Phase 0)

Before any code change, in a scratch project outside the repository, install the published old version and record every public method's answers to normal, edge and odd inputs (empty strings, numbers where strings go, null and undefined, NaN, negative and out-of-range numbers, huge values, array-likes and Sets, wrapper objects, characters outside the Basic Multilingual Plane). Templates: `scripts/golden-capture-npm.template.cjs` with `templates/npm/test/golden/codec.cjs` (a plain JSON round trip turns NaN and Infinity into null and -0 into 0, the very inputs the capture exists for), `scripts/golden-capture-nuget.template.cs`. A package that calls back, returns Promises or makes requests is captured against a local fixture server started by the capture script, recording each callback's timing, uncaught exceptions and every request the server saw; the internet never enters a recorded case (the system's reference has the recipe). A package with a command line records the published bin's output too: a CLI can be broken while the library works. Commit the JSON, the script as run and the codec. The golden test asserts exact equality and names each deliberate exception in one place; never regenerate the file from the new code, never compare with a tolerance. From the Phase 0 commit on, the golden JSON, the capture script and the codec never change: when the golden test fails, the fix goes in `src/`, or the difference becomes a named exception that the maintainer ruled on in the plan; editing the recording to match the new code is the failure this whole phase exists to prevent (agents reviving repositories edit failing tests; RepoRescue, 2026). A green golden suite counts only after it has been seen red: commit the rewrite, plant one wrong line in `src/` (a changed return, a flipped comparison), build, watch the golden test fail, revert with `git checkout -- <that file>`, watch it pass, and log both runs (before a commit, `git checkout` would restore the old source over the rewrite: L-074 `commit-before-canary`). Fixtures cover only what they record: read ported arithmetic line by line and write oracles from reference implementations for anything algorithmic. Pin the new major's additions in a second golden file captured from the release build.
