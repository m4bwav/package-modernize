# NuGet: how each phase is done

Coverage: **complete from one run (TrailerClipper, 2026-09-27: every phase including the golden capture, the replay, the independent review, the prerelease rehearsal and verify-published), plus two earlier looser runs and current docs**. Worked examples of the workflows: m4bwav/TrailerClipperLib `.github/workflows/ci.yml`, `release.yml` (tag check against every packed project, attestation job, environment-gated push job without checkout) and `verify-published.yml` (both indexes, signature, fresh consumers on three OSes, the published tool). The earlier runs: DotNetJsonPrettyPrinter (package JsonPrettyPrinter, .NET 3.5 to netstandard2.0 and net10.0, versions 2.0.0, 2.1.1 and 3.0.1) and DotNetRandomNameGenerator (RandomNameGeneratorLibrary, project.json to the same targets, 2.0.0, 2.0.1 and 2.1.0), both on 2026-09-24 and 25, published through nuget.org Trusted Publishing from a GitHub environment. They walked the phases loosely (no golden capture, no separate release workflow, no verify workflow, no independent review, tags pushed before CI was green twice), so this file says what the runs did and what the skill does instead. F#: IsImageUrlDotNet (2026-09-27, every phase: 0 and 1 in a Linux cloud session, the rest on Windows; 2.0.0 released and verified; see "F# packages" below). Registry facts were checked against learn.microsoft.com, github.com/NuGet and GitHub Docs on 2026-09-25 (RESEARCH.md has the sources); items marked *unverified* have no run behind them yet. The phase list and shared rules are in [../SKILL.md](../SKILL.md).

## Phase 0: survey and baseline

- `scripts/survey-nuget.sh PACKAGE_ID [OWNER/REPO]`: versions from the flat container (listed and unlisted), the search entry (total downloads, verified prefix, owners, deprecation, vulnerabilities), the registration index (per-version `listed`, published date, deprecation, dependency groups by target framework), the nupkg's file list and nuspec, then the GitHub side.
- In the clone: every `.csproj`, `.sln` or `.slnx`, `Directory.Build.props`, `.nuspec`, `packages.config`, `project.json`, `global.json`, the tests, the README, every dotfile. Old projects often carry a checked-in `packages/` folder or a `.nuspec` beside the csproj.
- Baseline: `dotnet --list-sdks`, then `dotnet restore`, `build`, `test` as they are. A .NET Framework 3.5 or 4.0 project, or a project.json one, will not build on a machine with only the .NET 10 SDK; record that as a fact and use the old test files as the behaviour record. `dotnet list package --outdated --include-transitive` and `dotnet list package --vulnerable --include-transitive` (`dotnet package list` from .NET 10) on the old project if it restores.
- Golden capture (first used on TrailerClipper, 2026-09-27; before that neither run did it, and both changed observable output without a fixture guarding it: JPP 2.0.0 rewrote its expectation file to System.Text.Json's output, RNG 2.1.0 changed seeded name output). Copy `scripts/golden-capture-nuget.template.cs` into a scratch console project that references the published old version (`dotnet add package ID --version OLD`), fill in every public method with normal, edge and odd inputs (null, empty, whitespace, invalid input, culture-sensitive values under two cultures), run, commit the JSON and the program under `tests/Golden/`. A `PackageValidationBaselineVersion` pointing at the published version covers the API shape, not the behaviour. A net40-era package that references a .NET Framework-only assembly (`System.Web.Extensions`, `System.Web`) cannot load on net10.0: capture on `net48` with `Microsoft.NETFramework.ReferenceAssemblies` (PrivateAssets all), the `System.Text.Json` package and `LangVersion latest`, and record net48's exception messages (the new net10.0 build words ArgumentException messages differently; compare type and first line there and name it). A package that drives an external program (ffmpeg, git, an image tool) is captured against real fixture files: every case in a fresh copy of the fixtures with the current directory set there, the resulting file tree recorded with a measured property per output (duration by ffprobe, dimensions, hash), console output kept, and the scratch path replaced by a token so the file is portable (TrailerClipper: 148 cases, 28 s, identical over two runs). Values that depend on the external program's build (MP3 encoder padding) get a named exception decided from a real CI run.
- One recording per runtime a caller can have (IsImageUrlDotNet, 2026-09-27). A `lib/net45` package that references only mscorlib, System and FSharp.Core also restores into a net10.0 console (NU1701, the .NET Framework fallback) and runs there, and its answers differ by runtime wherever it leans on `Path`, `Uri` or `WebRequest`. Multi-target the capture project (`net10.0;net48`) and commit `OLD.net10.0-linux.json`, `OLD.net48-windows.json` and so on, each captured from the published package by the same program; the golden test then compares each runtime with its own recording and needs no runtime exceptions. Put the SHA-256 of the loaded old DLL in the recording's header: it proves the answers came from the published file.
- Capturing on Linux (a cloud session): the .NET SDK comes from Ubuntu's archive when Microsoft's download hosts are blocked (`apt-get install dotnet-sdk-10.0` gave SDK 10.0.112 on Ubuntu 24.04), and Mono 6.8 from `mono-complete` runs a net48 build (`mono Capture.exe`). Mono is not .NET Framework: on IsImageUrlDotNet it disagreed with .NET 10 in 12 of 117 results and in most request heads, so keep a Mono recording as a reference only and take the .NET Framework recording from a `windows-latest` runner (a throwaway workflow on a scratch branch that runs the capture twice, compares, and uploads the JSON as an artifact). Check push access (`git push --dry-run origin HEAD:refs/heads/probe`) before planning on a runner: the session may hold a repository read-only.
- A network capture on .NET: a raw `TcpListener` fixture server on 127.0.0.1 that is also `WebRequest.DefaultWebProxy`, with every case on a `.test` host (RFC 6761, never resolves) and non-HTTP schemes on 127.0.0.1, so every request arrives in absolute form at the fixture and a bypass would fail rather than reach the internet; https arrives as CONNECT (answer 403). Record each case's request heads; normalise the free port, the work folder and the current directory to tokens, and the drive root too (a `file:///x` case names the current drive on Windows; L-075 `recording-names-the-drive`). .NET 10 routes even loopback URLs through the proxy. The golden test of such a package lives alone in its own test project: on .NET Framework, request heads changed when other network tests ran earlier in the same process (L-072 `golden-alone-in-process`).
- Read every version's nupkg, not only the latest (the survey script lists the newest ten since 2026-09-27): CachingServiceWithAOPSupport 1.0.0 packed its DLL under `bin/Debug/` with the source files, PDBs and `obj/` caches (one names the 2015 machine's user folder), so it installed no reference at all, while 1.0.1 was fine (L-078 `survey-every-version-nupkg`).
- When the old projects cannot build (non-SDK csproj, no targeting pack, MSTest from Visual Studio), compile the old test files unchanged, by `Compile Include` links, in a scratch SDK-style net48 project with the current MSTest and the published package: CachingServiceWithAOPSupport's 13 tests of 2015 passed that way against 1.0.1, a baseline the MSB3644 build could not give (L-079 `old-tests-against-published`).
- Record the process bitness in the capture header and run the golden replay the same way: a .NET Framework capture run as AnyCPU is 64-bit, a test exe pinned to win-x86 is 32-bit, and the int.MaxValue OutOfMemoryException message differs between them (RandomNameGeneratorLibrary, 2026-09-28; the replay pins win-x64).
- Record the CPU architecture too (`RuntimeInformation.ProcessArchitecture`): GitHub's macos-latest is arm64, where the runtime raises DivideByZeroException and OverflowException for `long %` from a helper in System.Private.CoreLib, so an exception's `TargetSite` (and a recorded `$from`) names CoreLib there and the library on x64 (FizzBuzzPlus, 2026-09-29; L-137 `exception-source-depends-on-cpu`).
- Culture: .NET 5 and later format numbers with ICU data, which writes a negative number as U+2212 plus the digits in sv-SE and nb-NO, and puts U+200E (he-IL, fa-IR) or U+061C (ar-SA) before the sign; .NET Framework wrote "-" in all five. Code that formats a number with the current culture (string concatenation included) therefore changes its output when it moves from net4x to .NET. Capture negative numbers under those cultures on both runtimes (FizzBuzzPlus, 2026-09-29; L-138 `icu-minus-sign`).
- Tokens in recorded text: replace the work folder with `{WORK}` and, in the same text, the directory separator with "/", inside the case, so one recording serves Windows, Linux and macOS (L-095 `portable-path-token`, 2026-09-28).
- A Framework-era package whose dependency cannot load on .NET Core still gets a net10.0 recording, as a record of failure: CachingServiceWithAOPSupport 1.0.1 restores into net10.0 (NU1701), but Castle.Core 3.2.2 fails every proxy there with FileNotFoundException for System.Security.Permissions, while its plain classes answer. The net48 recording is then the contract on every runtime, and the golden test compares net10.0 with it plus the ArgumentException ` (Parameter 'x')` suffix as a named exception (L-080 `net10-record-of-failure`).
- Read the old nupkg's file list, not only its nuspec: TrailerClipper 1.1.0 declared no dependency yet shipped MediaToolkit.dll (10.8 MB, with an embedded ffmpeg.exe) and System.Net.Http.dll in a `lib/` folder with no target framework. Bundled third-party DLLs are undeclared dependencies and a security item for the plan. Old repositories also commit their nupkgs despite `*.nupkg` in `.gitignore`.
- Dead services on .NET repos: AppVeyor (`appveyor.yml`, badge), Travis, MyGet feeds, Coveralls, codecov, NuGet badges from dead hosts (run `node scripts/check-readme-images.mjs README.md --registry nuget`: nuget.org renders images only from its allow-list of hosts and never from relative paths, and shows the warning to package owners only; list checked on learn.microsoft.com, updated 2026-07-07); the VS `.gitignore` template's `[Ll]og/` line, which swallows `ai-docs/log/`.

## F# packages (IsImageUrlDotNet, 2026-09-27)

What differs from a C# package. Phase 0 to 3 facts are from the run (Phase 2 and 3 verified on 2026-09-27, pull request m4bwav/IsImageUrlDotNet#1).

- **FSharp.Core is the dependency that matters.** An F# assembly always references FSharp.Core. Old nuspecs often forgot to declare it (IsImageUrlDotNet 1.0.2 references FSharp.Core 4.4.0.0 and declares nothing, so a C# project without FSharp.Core fails on first use); read the DLL's references (`monodis --assemblyref` on Linux, or reflection), not only the nuspec. The SDK adds an implicit FSharp.Core reference whose version follows the SDK's feature band (SDK 10.0.112 resolves FSharp.Core 10.0.112; the 10.0.4xx band resolves 10.1.4xx), so a library that keeps it gets whatever floor the build machine had. Pin it: `<DisableImplicitFSharpCoreReference>true</DisableImplicitFSharpCoreReference>` and an explicit `PackageReference` to the lowest version the code needs (the F# team's guidance in dotnet/fsharp `docs/fsharp-core-notes.md`: pin, never bundle FSharp.Core). `task { }` needs 6.0; 6.0.7 (2022-11-07) is the last 6.0 patch; 4.7.2 is the last with a net45 build; no FSharp.Core version carries an advisory (checked 2026-09-27). The flat container lists FSharp.Core 11.0.100, which is unlisted: take "latest" from the registration index.
- **Formatting: Fantomas, not `dotnet format`.** `dotnet format --verify-no-changes` on an fsproj prints "Format currently supports only C# and Visual Basic projects" and exits 0, so the template's CI step passes on any F# code. Use Fantomas as a local tool (`dotnet new tool-manifest`, `dotnet tool install fantomas`, `dotnet fantomas --check .`, exit 99 when a file needs formatting) with a `.fantomasignore` for the frozen capture. The .NET analyzers (`EnableNETAnalyzers`, `AnalysisLevel`) do not apply to F#; the maintained F# analyzers (G-Research.FSharp.Analyzers, Ionide.Analyzers) run through the `fsharp-analyzers` tool and must match the SDK's compiler, so try them before promising them. Warnings as errors plus `--warnon:1182,3390` (unused values, XML doc) is the floor. Verified 2026-09-27: fsharp-analyzers 0.39.2 with G-Research.FSharp.Analyzers 0.25.0 and Ionide.Analyzers 0.19.0 run on SDK 10.0.401; CI runs them on Linux with `--treat-as-error '*'`, the packs as `PackageDownload` in the library project, and `--exclude-files` for the frozen old code only (L-076 `fsharp-analyzers-verified`). F# nullness (`Nullable enable`) works with FSharp.Core 6.0.7; that version has no `NonNull` pattern, so narrow with `match x with | null -> ... | x -> ...`.
- **C# callers and extension methods.** A module marked `[<Extension>]` compiles to a static class C# can call as `url.IsImageUrl()`, but F# ignores the extension attributes of F# assemblies (it reads the module signature), so an F# capture or test cannot use the extension form: record the attributes by reflection and test the form from a small C# project. Module functions cannot take optional or overloaded parameters; a C#-friendly addition goes on a static class with `[<Optional; DefaultParameterValue>]` parameters.
- **The capture in F#.** A console fsproj with the old package, FSharp.Core pinned, `net10.0;net48`, and a hand-written JSON writer (the same text on every runtime, no serializer version in the way; build any `\u` escape from `char 92`, per L-058 `tool-unescapes-backslash-u`). Split it into `Json.fs`, `FixtureServer.fs`, `Cases.fs` (every case, touching only public names) and `Program.fs` (header and output): the golden test can then compile `Cases.fs` and the server unchanged against the new library, instead of a generated copy of the runner (the C# route of L-059 `golden-replay-from-capture`). Empty `Directory.Build.props`, `Directory.Build.targets` and `Directory.Packages.props` beside the capture project stop it from inheriting the repository's MSBuild files, so later changes cannot alter the recording (a sturdier fix than gitignoring its lock file). IsImageUrlDotNet: 117 cases, under a second, byte-identical over two runs on .NET 10 and on Mono.
- **Tests.** F# NUnit 4 projects work on net10.0 and net48 like C# ones; keep one C# test project for what only C# sees (extension syntax, a consumer that gets FSharp.Core transitively). The golden test compiles the capture's `Json.fs`, `FixtureServer.fs` and `Cases.fs` by link, unchanged, in a project of its own; it sets the ambient culture from the recording (en-US on Windows, invariant on Linux and macOS) as the capture ran. The F# test project needs `Nullable disable` and `NoWarn 44` for the frozen files, which the project adapts to, never the reverse.
- **FSharp.Core in Dependabot.** The library's FSharp.Core is its declared floor: `ignore` it in dependabot.yml so no bot pull request raises every caller's floor.
- **An API that makes requests.** A shared `HttpClient` that follows no redirect by itself (SocketsHttpHandler with `PooledConnectionLifetime` on net5+, HttpClientHandler elsewhere, `AllowAutoRedirect = false`) and a loop that follows a few, http and https only and never https to http, with a User-Agent naming the package. .NET 10's own handler follows a `Location` of another scheme as http (`ftp://h:1` opens a connection; `file:` throws UriFormatException): catch that from a caller's client and say in the README that a client for untrusted URLs sets `AllowAutoRedirect = false`. The IsImageUrlDotNet review found both.

## Phase 2: rewrite

- Branch `v<major>`. Remove the old csproj or project.json, `.nuspec`, `packages/`, `packages.config`, AppVeyor and Travis files; add the templates from `templates/nuget/` (`Library.csproj.template`, `Directory.Build.props`, `global.json`, `.editorconfig`, `.gitattributes`, `.gitignore`, workflows, Dependabot, `CLAUDE.md`, Copilot pointer) and write AGENTS.md, SECURITY.md, README (badges: NuGet version, downloads, CI), CHANGELOG (Keep a Changelog; the first paragraph of the new major states the compatibility promise and every exception).
- Golden test first against the capture; then the source, the rest of the tests, the docs. The replay that worked (TrailerClipper, 2026-09-27): generate the test's runner from the committed capture program by a mechanical rewrite (Main becomes a method returning the JSON; a header comment says how it was made; `#pragma warning disable` and `generated_code = true` in `.editorconfig` for it), so the replay provably asks the same questions; compare each case as JSON text and allow differences only in one exception table keyed by method, culture and arguments. First build 138 of 150, the rest named exceptions; the canary turned 16 red.
- A rewrite that reimplements a dependency the new targets lack (JavaScriptSerializer, System.Web, WebRequest details) gets a differential test against the original on net48: edge cases plus seeded random inputs, compared as text. CachingServiceWithAOPSupport's review found seven key differences that its 50 golden key cases missed; ReviewTests.R12 there is the example (L-086 `differential-against-the-original`, 2026-09-27).
- Public API with parameter names: when the old package cannot serve as a `PackageValidationBaselineVersion` (a net40 assembly), list its public types, members and parameter names by reflection from the published DLL into a committed text file (`PublicApi-OLD.txt`) and test that the new assembly still has every line. Package validation compares no parameter names anyway, and callers use named arguments: the TrailerClipper review found a renamed pair the golden replay could not see.
- A console app or tool that can write a long output: `Console.OpenStandardOutput()` swallows a closed pipe on Windows and Unix, so `app | head -1` can run forever. Write to a FileStream on the standard output handle (descriptor 1; `GetStdHandle(-11)` through LibraryImport on Windows), end quietly on a broken pipe (EPIPE 32; Windows 109 or 232), report any other write failure with exit 1, and test the real process with a reader that closes early (FizzBuzzPlus, 2026-09-29; L-142 `console-stream-swallows-epipe`).
- A console app that was never published becomes a .NET tool: a second project with `PackAsTool`, `ToolCommandName`, `RollForward Major`, its own `PackageId` (the Trusted Publishing policy then needs the scope that allows new packages, and a glob covering both ids).
- A package that drives an external program (ffmpeg): run it through a maintained wrapper if the maintainer wants one, find the program without configuration (option, environment variable, rooted PATH entries only, then the usual install folders such as winget's Links and Packages, Homebrew, Chocolatey, Scoop), never download it from the library, and let the tool install it through the OS package manager with a prompt (and `--yes` when stdin is not a terminal). Wrappers that build one argument string (FFMpegCore) quote paths without escaping: refuse file names with `"`.
- Verify locally: `dotnet restore --locked-mode`, `dotnet format --verify-no-changes`, `dotnet build -c Release`, `dotnet test -c Release` (net10.0 and net48), `dotnet pack -c Release -o artifacts` (package validation runs here), and a scratch console project that references the packed nupkg from `artifacts/` as a local source. Push, open the pull request with a "For review" list.

## Phase 3: review

`prompts/review-subagent.md` with the NuGet substitutions: compare against the published old package in a scratch project, fuzz odd inputs, check the public API surface (package validation output, or `PublicAPI.Shipped.txt` from `Microsoft.CodeAnalysis.PublicApiAnalyzers` if the package adopts it), culture and encoding behaviour, thread safety of lazily loaded data.

## Phase 4: CI, settings, merge, cleanup

- `ci.yml` (build, format check, test on Ubuntu and Windows, pack on Linux, artifacts kept) and `release.yml`, `verify-published.yml`, `dependabot.yml` from the templates. Pin actions to commit SHAs (the runs used major tags: `actions/checkout@v7`, `actions/setup-dotnet@v6`, `actions/upload-artifact@v7`, `actions/download-artifact@v8`, `NuGet/login@v1`, `softprops/action-gh-release@v3`; every one of them declares `using: node24`, and `NuGet/login` v1.2.0 at the template's SHA 8d19675 does too, checked 2026-09-26 after GitHub dropped node20 actions); `permissions: contents: read` at the top; `persist-credentials: false`; actionlint clean.
- Ruleset on `master` (deletion and non-fast-forward blocked, required check `ci`, admin bypass); squash-merge after the maintainer's review.
- GitHub environment `nuget`: required reviewer (the maintainer), deployment branch and tag rule `v*`, secret `NUGET_USER` = the nuget.org profile name (not the email). This is the human gate, because nuget.org has no staging.
- Cleanup as for npm: webhooks, old bot pull requests closed with one comment naming the merge commit, issues answered with the accurate history, `gh repo edit`, secret scanning and push protection, private vulnerability reporting, workflow permissions read.

## Phase 5 and 6: release rehearsal, release, verification

- Trusted Publishing policy, once, by the maintainer on nuget.org (user menu, Trusted Publishing, add policy): Repository Owner `OWNER`, Repository `REPO`, Workflow File `release.yml` (file name only), Environment `nuget`, scope "push only new package versions" with the glob set to the package id (when the release adds a new package id, such as a tool package, the scope must allow new packages: TrailerClipper used "push new packages and package versions" with the glob `TrailerClipper*`). The policy is temporarily active for seven days until the first publish binds GitHub's repository ids to it. Both runs published from `v*` tag runs through it, so tag-triggered runs are accepted. The workflow trades the job's OIDC token for a one-hour key with `NuGet/login@v1` (`permissions: id-token: write`); no API key is stored (new keys are capped at 30 days from 2026-08-17 and every older key expires on 2026-11-01).
- The gate: the push job references `environment: nuget`, so the run pauses until the maintainer approves it in the browser (Review deployments on the run; approving through `gh api .../pending_deployments` was refused in the runs). Nothing is on nuget.org before that click; after it, the push is live within about 15 minutes, no undo except unlisting.
- Rehearsal (verified on TrailerClipper 2.0.0-beta.1, IsImageUrlDotNet 2.0.0-beta.1 and CachingServiceWithAOPSupport 2.0.0-beta.1, 2026-09-27; the version change goes through a small pull request, since the master ruleset requires `ci`): `<Version>X.0.0-beta.1</Version>`, tag `vX.0.0-beta.1` after CI is green, approve, then verify. nuget.org treats prerelease versions separately (consumers opt in with `--prerelease`), so a beta does not become anyone's default. The test gallery `int.nugettest.org` is the other rehearsal route; its packages may not be preserved.
- Release: date the changelog, set the version, merge, wait for `ci` green on `master`, tag, push the tag, stop for the approval. Tag only after green: JPP tagged with the push twice, both tags landed on failing commits, force-pushing tags was refused, and versions 2.1.0 and 3.0.0 were burned.
- Verify (`verify-published.yml`, *unverified* as a workflow; the checks are the ones the runs did by hand): the flat-container index lists the version (`https://api.nuget.org/v3-flatcontainer/ID/index.json`, usually under 15 minutes); the registration entry has `listed: true` (the index lagged about 25 minutes once, with NU1102 in a consumer meanwhile); `dotnet nuget verify PACKAGE.nupkg` on the downloaded file (repository signature present); a fresh console project on net10.0 (and net48 on Windows) restores the exact version from nuget.org and gets the golden answers; the snupkg is on the symbol server; `gh attestation verify` on the attested nupkg from the run's artifact (the downloaded file has a different hash because nuget.org adds its repository signature after upload; nuget.org itself does not yet show provenance, NuGet/Home #13581).
- Unlisting is the maintainer's task (UI, or `dotnet nuget delete ID VERSION` with a scoped key; on nuget.org it unlists); deprecation (Legacy, critical bugs, other; alternate package; message) is UI only and does not unlist; permanent deletion does not exist.

## Retrofit

The NuGet side of [retrofit.md](retrofit.md), from RandomNameGeneratorLibrary 2.2.0 to 2.3.0 and JsonPrettyPrinter 3.0.1 to 3.0.2 (2026-09-28; moved here from retrofit.md on 2026-09-29).

- Gap table items of its own: the public API list with parameter, protected and init-only names (templates/nuget/tests/Golden/ApiList), the package validation baseline, one golden recording per runtime (net48 and net10.0), and the `nuget` environment with its required reviewer.
- Old versions through the capture (retrofit.md gap audit steps 1 and 7): when most downloads are on an old version, run the capture's deterministic cases that its API allows against it and write every difference into the next changelog. Do it with the capture itself (L-110 `one-capture-many-versions`): a version property on the package reference and `#if` blocks for the oldest API, recordings in `tests/Golden/upgrade/`, a compare script that reports CRLF-only differences apart. JsonPrettyPrinter's showed that its 2.0.0 serializer switch changed about fifteen things the changelog did not name, and that every 1.x version answered alike.
- Old majors: install the latest version of each old major in a scratch folder and import it once; one that no longer loads is a deprecation recommendation. Load it on every runtime a caller can have: JsonPrettyPrinter 1.x loads on .NET 10, but half its API throws there.
- A ruled fix: the changed answers go in a separate file beside the replay project (`Exceptions/<new version>.<topic>.<runtime>.json`), not under `tests/Golden`, so `git diff --exit-code <phase-0> -- tests/Golden` stays meaningful. The replay can write the differences on request (an environment variable, never set in CI); the file is then reviewed like code. Check `git diff --exit-code <phase-0> -- tests/Golden` after the fix. For a seeded list, the oracle is the new list indexed by the same `Random` draws; for a data file, the file against the rebuilt hash.
- A root `Directory.Build.props` from the template sets `IsPackable` false and repeats settings the csproj files already carry; when they do, add only the audit switches (JsonPrettyPrinter) rather than move settings and risk an unpackable library.

### Retrofit traps

- The published old version was recorded in a 64-bit .NET Framework process; the replay ran 32-bit and one OutOfMemoryException message differed. Record the process bitness in the capture's header and run the replay the same way.
- Adopting `* text=auto eol=lf` in a clone checked out with autocrlf leaves CRLF working files, and `dotnet format` then reports ENDOFLINE everywhere; after committing, `git rm -r --cached . && git reset --hard` rewrites them.
- The package content check lists files in C-locale order, which depends on the package id (README.md sorts before an id starting with Ra); build the expected list with the same sort.
- `{{` also matches GitHub Actions expressions; grep for `{{[A-Z_]+}}` and `TEMPLATE` after adapting templates.
- zizmor 1.30.1 requires a Dependabot cooldown of at least seven days, for every ecosystem.
- The package content check in ci.yml died without a message on a package with no dependencies: the nuspec's empty groups are self-closing, and a grep with no match ends a step under `-e` and pipefail. Run each new check locally with `bash -e -o pipefail` on the real nupkg, with a right and a wrong expectation (L-103 `empty-dependency-group`).
- A new test project must carry every extension the workflow's test flags need (`--coverage` needs Microsoft.Testing.Extensions.CodeCoverage), or Microsoft.Testing.Platform exits 5 with "Zero tests ran" (L-101 `ci-command-locally`).
- xunit.v3 4.x made `CollectionBehavior(DisableTestParallelization = true)` an error (CS0619); a replay in one test class needs no attribute.
- JsonElement.GetString() throws on .NET Framework for a recorded lone surrogate; with one recording per runtime, compare strings by raw JSON text (L-117).
- A hidden overload in an older major (JsonPrettyPrinter 2.x kept a constructor taking its old context) makes `new X(null)` ambiguous when the capture compiles against it: cast every null (L-110).
- The Linux leg is where an OS-dependent answer shows; push early so CI runs the replay on Ubuntu before the review (L-119).

## Traps (from the runs of 2026-09-25 and TrailerClipper, 2026-09-27)

- A capture project inside the repository inherits `Directory.Build.props`; an IDE restore then writes a `packages.lock.json` into `tests/Golden/Capture/`, and `git add -A` commits it. Gitignore it; the untouched-golden check (`git diff --exit-code <phase-0> -- tests/Golden`) caught it.
- An embedded resource whose bytes the capture recorded (a help text with BOM and CRLF) must be `-text` in `.gitattributes`: old repositories stored it LF, so only Windows checkouts had CRLF and Linux CI would differ.
- CI for a package that measures an external program's output: pin a current build on every OS. Ubuntu 24.04's apt ffmpeg is 6.1, whose ffprobe measured an untouched MP3 as 10 031 ms instead of 10 000; CI takes BtbN/FFmpeg-Builds' latest 9.0 build and checks it against the release's checksums.sha256. macOS lists directory entries in a different order (sort them in the library when the order is observable) and reaches the temp folder through `/private` (resolve the working path before replacing it in recorded text).
- The template `.editorconfig` section for tests must match the layout: `[*Tests/**.cs]` matches nothing under `tests/X.Tests/`; use `[tests/**.cs]`.
- The registration index took about 23 minutes for JsonPrettyPrinter 3.0.2 (2026-09-29), longer than verify-published's old 20-minute wait; it now waits up to 60 minutes (L-122 `registration-lag-past-20-minutes`).
- verify-published must wait for both nuget.org indexes: the flat container lists a version first, but `dotnet tool install` and restores read the registration index, which committed TrailerClipper.Tool about a minute later and failed the check on two OSes (2026-09-27).
- The editor tools decode backslash-u escapes in the text they write, and Git Bash heredocs halve backslashes: a C# escape for "<" became a literal "<" and silently disabled the config escaping. Write such text through Python with chr(92) and grep the result.

- Adopting `* text=auto eol=lf` in a clone checked out with autocrlf leaves CRLF working files; `dotnet format` reports ENDOFLINE on each until `git rm -r --cached . && git reset --hard` after a commit (2026-09-28).
- xunit.v3 4.x turns `CollectionBehavior(DisableTestParallelization = true)` into error CS0619; a golden replay in one test class needs no attribute (2026-09-28).
- zizmor 1.30.1 flags a Dependabot cooldown under seven days, including an ecosystem with none (dotnet-sdk); the template uses seven (2026-09-28).
- Backslash-u escapes quoted in markdown prose are decoded by the editor tools as well: write code points as U+FFFD in documents (L-091 `prose-escapes-decode-too`, 2026-09-28).
- `dotnet format --verify-no-changes` exits 0 on F# projects without checking anything (2026-09-27); an F# repository needs Fantomas in CI.
- Reflection-based key or JSON writers see different public properties on .NET Framework and .NET: `TimeSpan` gained Microseconds, Nanoseconds, TotalMicroseconds and TotalNanoseconds in .NET 7, and .NET computes `TotalHours` exactly (0.025 where the Framework gave 0.024999999999999998). A golden case recorded on net48 then fails on net10.0 only; write such types in the Framework's shape (L-083 `bcl-shape-differs-by-runtime`, 2026-09-27).
- A cache or serializer that reads every public getter of its arguments blocks on a pending `Task` argument (`Result`), as JavaScriptSerializer did; a test that passes a `TaskCompletionSource` hangs the whole test host. Run new test suites with `dotnet test --blame-hang-timeout 60s --blame-hang-dump-type none`, which names the hanging test (L-084 `blame-hang-names-the-test`, 2026-09-27).
- A tag push under the admins-only tag ruleset prints "Cannot create ref due to creations being restricted" (under "Bypassed rule violations"); the tag is created. Read the ref back instead of retagging (L-087 `tag-bypass-message`, 2026-09-27).
- `gh attestation verify` exits 0 with no output outside a terminal; add `--format json` and log the workflow and ref of the statement (L-088 `attestation-verify-silent`, 2026-09-27).
- The flat container lists unlisted versions (FSharp.Core 11.0.100 on 2026-09-27); read `listed` and `published` from the registration index before calling a version the latest.
- NUnit 5.0.0 was published on 2026-09-27; runs that day kept 4.6.1 for the three-day cooldown. `scripts/nuget-latest.py` flags such versions (L-081 `nuget-latest-cooldown`).
- `survey-github.sh` needs a logged-in gh; without one it now stops with exit 2 instead of printing "(none)" lines (fixed 2026-09-27 after a cloud session printed false negatives).
- Bash steps on Windows runners: `dotnet nuget add source` refuses `/d/a/...` and `D:/a/...`; pass `cygpath -w`. A consumer built from `artifacts/` gets a nuget.config (two `--source` flags on SDK 10.0.401 read the URL as a local folder) and its own `NUGET_PACKAGES`, so setup-dotnet's cache cannot supply a stale copy of the same version (L-073 `windows-paths-for-dotnet-nuget`).
- `release.yml` refuses a tag whose commit is not on master (`git merge-base --is-ancestor "$GITHUB_SHA" FETCH_HEAD` after `git fetch origin master`) and runs the net48 tests on Windows before the push job (IsImageUrlDotNet review, 2026-09-27).
- A publish job without a checkout cannot use `setup-dotnet`'s `global-json-file`; pin `dotnet-version` there or add a checkout.
- `dorny/test-reporter` needs `checks: write` in its own job and a checkout (it runs `git ls-files`).
- Test code that also targets net48 cannot use `HashCode.Combine`, `string.GetHashCode(StringComparison)` or `init` without polyfills.
- MSBuild rejects `--` inside an XML comment in `Directory.Build.props` (MSB4024).
- The Write tool produced CRLF without BOM while the repository's `.cs` files were BOM plus LF; normalise after writing. Bash heredocs mangled backslash sequences twice; the Edit tool was reliable.
- A Latin-1 data file decoded as UTF-8 put U+FFFD into 49 names; resource-integrity tests catch that class of problem.
- xunit.v3 4.x runs only on Microsoft.Testing.Platform.
- The Visual Studio `.gitignore` template ignores `ai-docs/log/`; add `!ai-docs/log/` or use everlast's `log.md`.
- System.Text.Json with `WriteIndented` writes Environment.NewLine, so a Windows recording of it fails on Linux; look for CRLF in the recordings before the Phase 0 commit (L-119 `os-newline-through-a-dependency`, 2026-09-28).
- On .NET Framework, System.Text.Json (netstandard2.0) writes 0.1 as 0.10000000000000001 and -0.0 as 0, and throws for 1e400 where .NET 10 returns Infinity: a serializer helper's answers differ by runtime, so record both (JsonPrettyPrinter, 2026-09-28).
- JsonElement.GetString() throws on .NET Framework for a lone surrogate; replays compare raw JSON text (L-117, 2026-09-28).
- net48 exception messages drop the parameter name from the first line; record ParamName separately (L-111, 2026-09-28).
- actionlint and shellcheck are not on this machine and not on npm: download both release zips and pass shellcheck by absolute path (L-118, 2026-09-28).
