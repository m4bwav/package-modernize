# Scripts

Deterministic helpers the skill runs; each prints the command it ran above its output, so the output is evidence for `ai-docs/log.md`. Bash scripts run in Git Bash on Windows and in any POSIX shell; the Node scripts need Node 20 or later; nothing here installs anything or writes to a registry.

- [survey-npm.sh](survey-npm.sh): run first in Phase 0 for an npm package; registry metadata, versions, attestations, downloads, dependents, the published tarball's file list, every runtime dependency's distance from current, then the GitHub side.
- [survey-nuget.sh](survey-nuget.sh): the same for a NuGet package id; flat-container versions, search entry (downloads, owners, deprecation), registration index (listed flags, target frameworks, dependencies per version), the file list of every version's nupkg (newest ten, with a warning for assemblies outside `lib/`, which install nothing) and the latest nuspec, then the GitHub side.
- [nuget-latest.py](nuget-latest.py): `python nuget-latest.py ID [ID ...]`: the latest listed stable version of each id from the registration index, its publish date and age, vulnerability and deprecation flags, and the previous version; marks anything younger than three days (the install cooldown). Run it before every PackageReference a run adds or bumps.
- [survey-github.sh](survey-github.sh): the shared GitHub part (called by the two above, or alone): settings, security features, branches, rulesets, issues, pull requests, Dependabot alerts, webhooks, secrets, environments, workflows, every action pin with the runtime its action.yml declares at that ref (node20 and older marked DEAD: GitHub stopped running them on 2026-09-23), forks, releases, dead-service files and badges.
- [golden-capture-npm.template.cjs](golden-capture-npm.template.cjs): copy into a scratch project that installed the published old version, with [../templates/npm/test/golden/codec.cjs](../templates/npm/test/golden/codec.cjs) beside it; records every public method's answers, odd inputs included, as the JSON the golden test asserts. It reads the bin and the dependencies so it replays unchanged against the next major (L-123).
- [golden-capture-nuget.template.cs](golden-capture-nuget.template.cs): the same as a console Program.cs for a NuGet package (unverified by a run).
- [check-readme-images.mjs](check-readme-images.mjs): lists every image and badge in a README with what is wrong with it: a dead service (with its replacement), an HTTP error, a badge whose SVG says "not found", a relative path that breaks on the registry page, or (`--registry nuget`) a host outside nuget.org's allow-list. Run it in Phase 0 on the old README and the published one, and at verification on the new one; it exits 1 while anything needs fixing. `--offline` classifies without fetching.
- [preflight-tag-npm.sh](preflight-tag-npm.sh): run before every `npm version`; checks the tree, branch, that the tag is free, the CHANGELOG heading (and its date for a release), then lint, typecheck, check, test, the golden recording and the workflow shell; prints READY with the tag commands or NOT READY. Replays of is-an-image-url's beta.1 mistake fail it.
- [watch-run.sh](watch-run.sh): `OWNER/REPO WORKFLOW [RUN_ID] [--dispatch k=v]`; finds the run just started, waits, and prints the verdict per job plus the evidence lines (stage id, staging tag, provenance, release url) or the failing step's last 40 lines.
- [verify-registry-npm.sh](verify-registry-npm.sh): `PACKAGE VERSION [OWNER/REPO]`; the whole after-approval check in one call: dist-tags, provenance, not deprecated, scratch install with `npm audit signatures`, require/import/bin smoke, GitHub Release, and a verify-published run through watch-run.sh.
- [post-merge-cleanup.sh](post-merge-cleanup.sh): `OWNER/REPO PR DISPOSITIONS_FILE [--apply] [--ruleset-from OWNER/REPO/ID] [--tag-ruleset]`; Phase 4 cleanup from a tab-separated disposition file (pr, branch, hook; `{SHA}` for the merge commit), the branch ruleset copied from a finished repository, and the admins-only tag ruleset from `templates/rulesets/`. Dry run by default so the maintainer gives one go for the whole list; refuses while Dependabot alerts are open.
- [check-workflow-shell.py](check-workflow-shell.py): runs shellcheck (errors only; from PATH or `uvx --from shellcheck-py`) on every multi-line `run:` block of `.github/workflows/`, because actionlint skips shell when shellcheck is missing and `bash -n` passes an unclosed `[`. Run it with actionlint whenever a workflow changes; exits 1 on any error.
- [check-golden-untouched.sh](check-golden-untouched.sh): `[REPO_DIR] [GOLDEN_DIR]`; proves every recording file under `test/golden/` (`*.json`, `capture*`, `codec*`, `fixture-server*`) is unchanged since the commit that added it, so a failing golden test was fixed in `src/`, not in the recording. Phase 2 exit and, through preflight-tag-npm.sh, before every tag; exits 1 on any change.
- [check-next-tag-npm.sh](check-next-tag-npm.sh): `PACKAGE [PACKAGE...]`; read-only, no login; flags a `next` dist-tag below `latest` (semver order) and prints the move or remove command for the maintainer; exit 1 if any is stale.
- [check-line-endings.mjs](check-line-endings.mjs): counts byte 13 in files, since Git Bash's grep cannot; run before every commit on Windows.
- [make-icon.py](make-icon.py): `OUTPUT.png --text GLYPH | --picture image [--color #RRGGBB]`; draws a basic 128 by 128 package icon (a white glyph on a rounded square) for a package whose registry shows an icon and that has none (L-070 `generate-missing-icon`). Needs Pillow; look at the PNG before committing it.
