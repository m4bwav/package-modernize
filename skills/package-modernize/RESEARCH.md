## Current understanding

- **npm (complete, two runs).** Trusted publishing exchanges the GitHub Actions OIDC token for a short-lived token (npm 11.5.1+, Node 24 on the runner); staged publishing (`npm stage publish`, npm 11.15, GA 2026-05-22) holds a version until an owner approves with 2FA, and a trusted publisher can be stage-only ("Allow npm publish" unticked). Provenance is automatic for a public repository and package; `npm audit signatures` verifies signature and attestation. Classic tokens were revoked 2025-12-09; granular tokens live at most 90 days. npm 12 (2026-09-22) blocks install scripts by default. Toolchain verified 2026-09-25: TypeScript ~6.0.3 (7 waits for xo), tsdown 0.23.0 pinned, xo ^5.0.1, c8 ^12, publint ^0.3.24, attw ^0.18.5, Node matrix 20, 22, 24, 26 (Node 20 EOL 2026-04-30, Node 22 EOL 2027-04-30, Node 26 Active LTS 2026-10-28). Deno 2.9 skips npm versions under 24 hours old without `--minimum-dependency-age=0`.
- **NuGet (two runs plus docs).** Trusted Publishing GA 2025-09-22; policy fields Repository Owner, Repository, Workflow File (file name only), Environment (optional), scopes with a package glob; `NuGet/login@v1` (v1.2.0, 2026-04-24) mints a one-hour key; policies for private repositories are temporarily active for seven days until the first publish. No staging on nuget.org: the gate is a GitHub environment with a required reviewer on the push job. API keys: 30-day maximum from 2026-08-17, every older key expires 2026-11-01; 2FA mandatory on the Microsoft account. Repository signing is automatic; GitHub attestations work on a nupkg but nuget.org shows no provenance yet (NuGet/Home #13581 open); the downloaded file's hash differs from the attested one because of the repository signature. No deletion; unlisting through the UI or `dotnet nuget delete`; deprecation (Legacy, critical bugs, other, alternate package) UI only. NuGetAudit is on since SDK 8, `NuGetAuditMode all` by default for net10.0; the documented audit-pipeline pattern keeps a local build green while CI fails on findings. Package validation (`EnablePackageValidation`, `PackageValidationBaselineVersion`) is the API-shape golden. .NET 10 LTS to 2028-11-14; .NET 8 and 9 end 2026-11-10; SDK 10.0.401 current; .slnx is the default solution format from .NET 10; `actions/setup-dotnet@v6`. Indexing under 15 minutes usually; the registration index lagged about 25 minutes once. Both runs published from `v*` tag runs, so tag-triggered runs pass the policy.
- **PyPI (docs).** Trusted Publishing (15-minute tokens; fields owner, repository, workflow filename, environment), `pypa/gh-action-pypi-publish@release/v1` with PEP 740 attestations by default since v1.11.0; no registry gate (GitHub environment plus TestPyPI); yank per release, deletion permanent; 2FA mandatory since 2024-01-01; PEP 621 metadata, one build backend, `requires-python >=3.10` in September 2026 (3.15 in prerelease, 3.10 security until 2026-10).
- **crates.io (docs).** Trusted publishing since 2025-07-11 (30-minute tokens; `rust-lang/crates-io-auth-action@v1`, v1.0.5), first publish still needs a token; no gate on the registry; `cargo yank`; deletion within 72 hours or small crates only; edition 2024 default since Rust 1.85.0; stable 1.98.1; `cargo semver-checks` for API compatibility; `published_by` and `trustpub_data` on versions.
- **Maven Central (docs).** No OIDC; the Central Publisher Portal takes user tokens; OSSRH ended 2025-06-30; GPG signatures and sources and javadoc jars mandatory; the registry has the gate (VALIDATED until published, `publishingType=USER_MANAGED`); immutable once published; `central-publishing-maven-plugin` 0.11.0, no official Gradle plugin.
- **Go modules (docs).** No registry account or publish step; a tag is the release; `sum.golang.org` is the transparency log; `retract` and `// Deprecated:` in go.mod; `/v2` path suffix for majors; Go 1.27 and 1.26 supported; govulncheck; the proxy serves a new tag within about a minute.
- **Tooling and prior art (2026-09-25).** No skill or MCP server covers the producer-side chain; every found one covers at most three phases (Anthropic `code-modernization` for assess, brief and verify on large codebases; `doc-and-modernize` for feasibility spike and safety ladder; `Paldom/node-skills` for npm packaging and release; `dotnet/skills` `nuget-trusted-publishing` and `paulirish` `npm-trusted-publishing` for OIDC setup; `trailofbits` `open-sourcing` for the pre-public secrets audit; `lirantal/npm-security-best-practices` as the returning-maintainer checklist). Tools worth delegating to: knip, npm-check-updates or taze, publint, attw, size-limit, actionlint, zizmor, pinact, OpenSSF Scorecard, dotnet-outdated, package validation, PublicApiAnalyzers. The name `package-modernize` is free on npm, GitHub and skills.sh.
- **Tools and prior art as the skill applies them (checked 2026-09-26; moved from SKILL.md on 2026-09-30, C-20260930-1).** Delegate to tools rather than reinventing: knip (unused exports and dependencies), npm-check-updates or taze, publint and `@arethetypeswrong/cli --pack`, size-limit, actionlint, zizmor, pinact (SHA pinning), OpenSSF Scorecard for a before and after score, `gh api repos/OWNER/REPO/hooks` for webhooks, `npm deprecate`; for .NET, dotnet-outdated, `dotnet list package --vulnerable --include-transitive`, package validation with `PackageValidationBaselineVersion`, PublicApiAnalyzers. Point at, do not copy: Anthropic's `code-modernization` plugin (1.0.0, 2026-09-25) for a large legacy codebase (its assess, brief and verify vocabulary, byte-for-byte old-versus-new harness, and the canary: a planted one-line break must turn the golden suite red before its green counts), Evil Martians' `secure-npm-package` (the hardened stage-only release job, a `min-release-age` cooldown, an admins-only tag ruleset), Drydock (diff a staged npm version against the published one before the approval), `github/awesome-copilot` `doc-and-modernize` (feasibility spike, safety ladder), `Paldom/node-skills` (npm packaging and release specifics), `dotnet/skills` `nuget-trusted-publishing` and `paulirish/dotfiles` `npm-trusted-publishing` (OIDC setup and its error table), `trailofbits/skills` `open-sourcing` (the pre-public secrets audit), `lirantal/npm-security-best-practices` (the returning-maintainer checklist). Every found skill covers at most three of these phases and none covers the gated release or the registry-side verification; consumer-side upgrade skills and MCP servers help rank dependency targets in Phase 0 only. Agents reviving repositories edit failing tests (RepoRescue, 2026): the golden files and the capture never change after Phase 0 (the Phase 2 canary and untouched check; `scripts/preflight-tag-npm.sh` repeats the check before every tag). RESEARCH.md keeps the list with dates.
- **Practice (2026).** The failure modes others report: agents grep instead of understanding and break dependants; hallucinated APIs and package names spread through skill files (slopsquatting: a hallucinated name in 47 SKILL.md files reached 237 repositories); "test theater"; behaviour drift from helpful cleanups; source maps shipped by accident (Claude Code 2.1.88, 2026-03-31); worms republishing through stolen long-lived tokens (Shai-Hulud 2025, CHAINDROP 2026). The counters that the skill adopts: golden capture before any change, characterization tests green on the unmodified code first, one bounded transform at a time, an independent review from artifacts rather than the transcript, a `files` allowlist with a pack-list test, staged or gated publishing, token rotation as the first cleanup.
